### 1.2 데이터의 입도(grain)

**1행 = 1개 리스팅(숙소 매물)의 특정 시점 스냅샷.**

시계열이 아닙니다. 날짜 컬럼이 있지만 모두 한 행 안의 속성일 뿐, 같은 숙소가 여러 시점으로 반복되지 않습니다.

```
842,655 행  =  53개 도시의 리스팅 전수
      ↓
  1 리스팅  →  호스트 정보(중복 포함) + 숙소 스펙 + 가격 견적 1건
               + 예약 가능 일수 + 리뷰 누적치
```

**리스팅 ≠ 물리적 숙소 수**입니다. 건물 전체를 1건으로 올리기도 하고(`beds` 최대 167), 한 집의 방을 따로 올리기도 합니다(`Private room` 19.2%). 또 **등록 ≠ 영업**입니다 — 갱신된 매물(source=0) 기준 **30.5%가 최근 1년간 거래가 없습니다.**

### 2.1 키 · 출처 (4개)

| 컬럼 | 타입 | 결측 | 의미 | 주의 |
|---|---|---:|---|---|
| `country` | str | 0% | 국가 (19개) | — |
| `region` | str | 0% | 도시/광역 (53개) | 실질적 지역 분석 단위 |
| `id` | int64 | 0% | 리스팅 고유 ID | 값이 클수록 최근 등록 |
| `source` | int64 | 0% | **데이터 갱신 여부** — `0` = 이번에 새로 수집 / `1` = **갱신 실패, 과거값 이월** | **가장 중요한 통제 변수** |

**`source=1`은 "다른 종류의 매물"이 아니라 "현재 상태를 모르는 매물"입니다.**

이번 수집 주기에 갱신되지 않아 과거 스냅샷 값이 그대로 남은 행입니다. 관찰되는 차이가 전부 여기서 나옵니다.

| 관찰 | 이월(carry-over)로 설명하면 |
|---|---|
| `price` 79% 결측 | 가격은 **실시간 견적**이라 이월이 불가능 |
| `bathrooms`·`beds` 100% 결측 | 이월된 과거 스냅샷에 이 필드가 아예 없었음 |
| `availability_365` 68%가 0 | 달력을 이월하지 못해 **0으로 채워진 것** — "닫힌 달력"이 아니라 **결측** |
| `id` 중앙값이 훨씬 작음 | 오래된 매물일수록 갱신 실패(내려갔거나 접근 불가) 확률이 높음 |

|  | **source = 0** | **source = 1** |
|---|---:|---:|
| 리스팅 수 | 678,897 (80.6%) | 163,758 (19.4%) |
| `bathrooms` 결측 | 7.0% | **100.0%** |
| `beds` 결측 | 2.9% | **100.0%** |
| `price` 결측 | 4.0% | **79.1%** |
| `availability_365` 중앙값 | 232일 | **0일** (68.3%가 0) |
| 리뷰 수 중앙값 | 11건 | 5건 |
| 호스트 수 | 326,858명 | 125,180명 (겹침 15,914명) |

**이월 시점은 행마다 다릅니다.** 단일 시점 스냅샷이 아닙니다. `last_review`로 역추적하면:

| | `last_review` 중앙값 | 95% | 최댓값 |
|---|---|---|---|
| source=0 | **2026-05-25** | 2026-06-26 | 2026-07-21 |
| source=1 | **2024-09-27** | 2026-06-17 | 2026-07-22 |

중앙값 기준 **약 20개월 전 값**이지만 꼬리는 2026년 6월까지 닿습니다. 각 행의 이월 시점은 알 수 없고, `last_review`가 그 **하한선**일 뿐입니다.

**같은 호스트로 비교하면 이월 효과가 분명히 보입니다.** 양쪽에 모두 나오는 호스트 15,914명의 매물만 떼어 보면:

| 같은 호스트의 매물 | source=0 (144,562건) | source=1 (37,820건) |
|---|---:|---:|
| `availability_365 = 0` 비율 | **0.1%** | **50.4%** |
| 누적 리뷰 0건 비율 | 22.4% | 25.1% |

같은 사람이 운영하는데 달력만 50%p 차이 → **운영 차이가 아니라 이월로 인한 정보 부재**입니다.

#### ⚠️ `source=1`에서 컬럼별로 믿을 수 있는 것과 없는 것

| 컬럼 | 신뢰도 | 이유 |
|---|---|---|
| `price`, `list_price`, `price_quote_*`, `bathrooms`, `beds` | ❌ **사용 불가** | 실시간 견적이라 이월 불가 / 과거 스냅샷에 필드 없음 |
| `availability_30/60/90/365` | ❌ **가장 위험** | **0이 "만실"인지 "미수집"인지 구분 불가** |
| `number_of_reviews_ltm` / `_l30d` / `_ly` / `reviews_per_month` | ❌ **기준 시점이 다름** | "최근 12개월"의 기준이 오늘이 아니라 **이월 시점** |
| `number_of_reviews` (누적), `first_review`, `last_review` | △ **하한값** | 이월 시점까지의 값. 오늘 기준으로는 과소추정 |
| `review_scores_*` | △ 과거 시점 평점 | 평점은 급변하지 않아 근사로는 사용 가능 |
| `host_is_superhost`, `minimum_nights`, `maximum_nights` | ⚠️ 과거 설정값 | 호스트가 바꿨을 수 있음 |
| `country`, `region`, `id`, `host_id`, `room_type`, `property_type`, `accommodates` | ✅ 사용 가능 | 거의 변하지 않는 속성 |

> **한 줄 요약: `source=1` 행으로는 "현재"를 말할 수 없습니다.** 시점이 개입하는 모든 분석은 source=0으로 한정해야 합니다.

### 3.2 결측은 랜덤이 아니다 — 6가지 구조적 원인

교차표로 **모든 결측의 발생 원인을 특정**했습니다. 이게 이 데이터 결측 처리의 전부입니다.

| 원인 | 해당 컬럼 | 증거 |
|---|---|---|
| **(A) 갱신 실패로 과거값 이월 (`source=1`)** | `bathrooms`, `beds`, `price` 계열 | 이월된 스냅샷에 필드가 없거나(`bathrooms`·`beds` **정확히 100.0%**) 실시간 견적이라 이월 불가(`price` 79.1%) |
| **(B) 논리적으로 값이 존재 불가** | `review_scores_*` 7종, `reviews_per_month`, `first/last_review` | 리뷰 0건 165,637건 ↔ 평점 결측 165,630건 **완전 일치** (예외 7건) |
| **(C) 예약 불가라 견적 미산출** | `price`, `list_price`, `price_quote_*` | `availability_365 == 0` 인 112,397건 중 **99.9%** 가 `price` 결측 — 단 그 112,397건의 **99.5%가 source=1**이라 (A)와 사실상 같은 현상 |
| **(D) 결측 = "해당 없음"이라는 상태값** | `discount_type` | 결측 ↔ `price == list_price` **100% 대응** |
| **(E) 도시별 수집 스키마 차이** | `neighbourhood_group_cleansed` | 53개 도시 중 **36개 100% 결측 / 17개 0% 결측 — 중간이 없음** |
| **(F) 자유 입력 미기재** | `host_location` | 유일하게 무작위(MCAR)에 가까운 결측 |

> **(C)의 함의가 가장 큽니다.** `price` 결측은 MCAR/MAR이 아니라 **MNAR(비무작위 결측)** 입니다.
> *"가격이 비어 있다 = 예약이 불가능한 매물"* 이라는 정보 그 자체이므로 **평균/중앙값으로 채우면 안 됩니다.**
> 채우는 순간 팔리지 않는 매물이 평균 가격의 정상 매물로 둔갑해 수익성 진단이 왜곡됩니다.

`neighbourhood_group_cleansed` 가 제공되는 17개 도시: barcelona, berlin, bordeaux, euskadi, greater-manchester, lisbon, madrid, pays-basque, porto, puglia, rotterdam, sevilla, the-hague, valencia, vaud, venice, zurich

**③ 대체할 때는 유사 그룹 기준으로, 대체 여부를 플래그로 남긴다.**

## 6. 핵심 발견 5가지

> 앞 장들의 수치에서 나온 결론입니다. 각 항목은 **한 줄 요약 → 근거 → 조치** 순서입니다.

| # | 발견 | 한 줄 |
|---|---|---|

### ① `source=1`은 과거값 이월이다 — "현재"를 말하려면 source=0만 써야 한다

**한 줄** — `source=1`(19.4%, 163,758건)은 이번 수집에서 **갱신에 실패해 과거값이 남은 행**입니다. 다른 종류의 매물이 아니라 **현재 상태를 알 수 없는 매물**입니다.

**근거 — 이월로 모든 패턴이 설명됩니다**

| 증거 | 값 | 이월로 설명하면 |
|---|---:|---|
| `price` 결측 | 79% | 실시간 견적이라 이월 불가 |
| `bathrooms`·`beds` 결측 | **100%** | 과거 스냅샷에 필드 자체가 없음 |
| `availability_365 = 0` | 68% | 달력 미이월 → 값이 아니라 **결측** |
| **같은 호스트** 내 `avail=0` 비율 | **0.1% vs 50.4%** | 운영 차이로는 설명 불가 (결정적 증거) |
| `last_review` 중앙값 | 2026-05-25 vs **2024-09-27** | 이월 시점이 평균 20개월 전 |

**왜 위험한가**

- **같은 `0`이 정반대 의미** — source=0의 `avail=0`은 70.1%가 최근 1년 내 리뷰 보유 → **"꽉 차서 0"(만실)**. source=1은 **"못 가져와서 0"**. 섞으면 만실과 미수집이 한 칸에 들어갑니다.
- **도시별 비중이 0%(아테네) ~ 48%(베를린)** — 통제 없이 비교하면 *"베를린은 가동률이 낮다"* 가 순전히 **갱신 실패율 차이**로 만들어집니다.

**→ 조치** — 시점이 개입하는 분석(가격·가동률·최근 수요)은 **`insightstay_core.parquet`**(651,090건)으로 한정. `room_type`·`accommodates`·`region` 같은 불변 속성만 전체 사용.

> 💡 **`source=1` 자체도 발견입니다.** 갱신 실패는 상당수가 이미 플랫폼에서 **내려갔을 가능성**을 뜻합니다. "공급 842,655건"이라는 숫자부터 재검토 대상입니다.

---

### ② 총액이 아니라 1박가(`price`)를 써야 한다

**한 줄** — 가격 컬럼 3개 중 객단가는 `price` 하나뿐입니다. 총액은 **견적 기간이 행마다 1~100박으로 달라** 비교하면 안 됩니다.

**근거 — 검증으로 관계를 확정했습니다**

```
price = price_quote_total_price ÷ 견적 숙박일수     (비율 전 구간 1.000)
price = list_price × (1 − 할인율)                   (price > list_price 0건)
```

| | A 매물 | B 매물 |
|---|---:|---:|
| 견적 기간 | 100박 | 1박 |
| 총액 | 10,000€ | 150€ |
| **1박 단가** | **100€** | **150€** |

총액으로 비교하면 A가 66배 비싸 보이지만 **실제로는 A가 더 쌉니다.** 총액 순위는 가격 순위가 아니라 **견적 기간 순위**입니다.

**→ 조치** — 객단가는 무조건 `price`. 할인은 `discount_rate = 1 − price/list_price`.

> ⚠️ `price`는 **성수기(6~8월) 견적의 할인 후** 1박 환산가입니다. 청소비 영향은 1박 견적에서 최대 6% 수준입니다 ([2.4절](#24-가격-6개)).

---

### ③ 죽은 재고 — 갱신된 매물 10채 중 3채가 최근 1년 거래 0

**한 줄** — 등록은 되어 있는데 돈은 안 되는 매물이 **30.5%** 입니다.

| 기준 | 전체 842,655 | **source=0 (유효)** |
|---|---:|---:|
| **최근 12개월 리뷰 0건** | 320,727 (38.1%) | **207,005 (30.5%)** |
| 누적 리뷰 0건 (한 번도 예약 안 됨) | 165,637 (19.7%) | 125,888 (18.5%) |
| 1년 이상 리뷰 없음 (리뷰 보유자 중) | 19.5% | **13.0%** |
| ~~향후 1년 예약 가능일 0일~~ | ~~112,397 (13.3%)~~ | 559 (0.1%) |

> 🚨 **`availability_365 = 0`은 죽은 재고 지표가 될 수 없습니다.** 112,397건 중 **99.5%가 source=1**의 미수집이고, source=0에서는 559건뿐인 데다 그중 **70.1%가 최근 리뷰 보유(=만실)** 입니다. 근거는 **`number_of_reviews_ltm == 0` 하나만** 쓰세요.

**왜 중요한가** — 플랫폼 수익은 **거래액의 15.5% 수수료**입니다. 거래 0 = 수수료 0인데, 검색 노출 자리와 호스트 지원 리소스는 계속 소모됩니다.

**→ 조치** — `source == 0 & is_dormant`로 집단을 분리해 원인(가격? 최소 숙박일? 리뷰 부재?)을 파고드세요. 여기에 **갱신조차 안 된 19.4%** 를 "이탈 후보"로 덧붙이면 문제 규모가 더 커집니다.

## 7. 분석 시 피해야 할 9가지 함정

| # | 함정 | 왜 위험한가 | 대응 |
|---|---|---|---|
| 1 | **`source` 미통제 도시 비교** | source=1은 **과거값 이월**. 비중이 도시별 0~48% → 갱신 실패율 차이가 시장 차이로 둔갑 | `insightstay_core.parquet` (source=0) 사용 |
| 2 | **`price_quote_total_price`를 객단가로 사용** | 견적 기간 1~100박 → "비싼 매물"이 아니라 "긴 견적"을 고름 | 반드시 `price` (1박가) |
| 3 | **`price` 결측을 평균으로 대체** | 팔리지 않는 매물이 정상 매물로 둔갑 → 수익성 과대추정 | 대체 금지, `has_price`로 분리 |
| 4 | **달력 가동률(`1 − availability/N`)을 수요로 해석** | blocked 일수 포함 → 거래 매물 안에서 리뷰 수와 순위상관 0.003, 도시 순위는 반대 방향. 게다가 **`avail=0`의 99.5%가 source=1의 미수집** | **`occ_review`(리뷰 기반 가동률) 사용.** 달력 가동률은 상대 비교에도 쓰지 않음 |
| 5 | **`maximum_nights = 1125`를 실제 제약으로 해석** | 33.8%가 플랫폼 기본값 = 미설정 | `max_nights_is_default` 로 제외 |
| 6 | **평점을 그대로 품질 지표로 사용** | 75분위가 이미 5.0(천장효과), 7종 상관 0.7~0.9(다중공선성) | 하위 꼬리와 `value`·`cleanliness` 중심 |
| 7 | **`host_id` 중복 무시하고 행 기준 평균** | `host_listings_total`이 **행 기준 23.68 vs 호스트 기준 1.84** — 12배 차이 | `groupby('host_id')` 로 접기 |
| 8 | **`_ly / _ltm` 로 전년 대비 성장률 계산** | 두 기간이 **겹칩니다.** 46.2%가 완전 일치, `_ltm + _ly > 누적리뷰` 인 행이 17.7% | 전년 비교 불가. 추세는 `first/last_review` 로 직접 계산 |
| 9 | **`reviews_per_month` 를 최근 활동량으로 사용** | **최초 리뷰 이후 생애 평균**입니다. 과거에 활발했다 죽은 매물도 높게 나옴 | 최근 수요는 `number_of_reviews_ltm` |

```python
import pandas as pd

df   = pd.read_parquet("data/processed/insightstay_clean.parquet")   # 840,616행 — 전체 공급 구조
core = pd.read_parquet("data/processed/insightstay_core.parquet")    # 651,090행 — 가격·수익성 분석

# 도시별 숙소당 수익성 = 리뷰 기반 가동률 × 객단가
# (occ_review 는 scripts/build_master.py 가 만든 마스터 데이터에 있습니다)
m = pd.read_parquet("data/processed/InsightStay_data_cleaned.parquet")
core2 = m[(m.source == 0) & m.price.notna()].assign(rev=lambda d: d.price * d.occ_review * 365)
core2.groupby("region").agg(
    n            = ("id", "size"),
    객단가       = ("price", "median"),
    가동률       = ("occ_review", "mean"),
    추정연매출   = ("rev", "mean"),
).sort_values("추정연매출", ascending=False)

# 죽은 재고
df[df.source == 0]["is_dormant"].sum()   # 206,375건 = 30.4%  (source=1은 이월이라 제외)
```
